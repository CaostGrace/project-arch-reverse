## Context

project-arch-reverse v3.0 的生成阶段按拓扑排序分层生成模块文档。Agent 在单线程中逐个生成模块文档（12章）和日志文档（5章），但无进度追踪。中断后无法恢复，失败无重试。

## Goals / Non-Goals

**Goals:**
- 章节级任务清单持久化，支持中断后精确恢复到中断章节
- 失败自动重试一次，两次失败后跳过并记录
- CP0 自动检测未完成任务清单并推荐恢复
- 任务清单作为策略（A/B/C/D）的扩展，不改变策略选择逻辑
- CP2.5 与任务清单联动验证完成度

**Non-Goals:**
- 不引入真正的断点续传（中断章节从 `[>]` 重置为 `[ ]` 后重新生成）
- 不改变模块文档的章节内容或格式
- 不改变拓扑排序逻辑
- 不引入 Agent 多实例并行生成

## Decisions

### D1: 任务状态机 — 5 状态模型

```
[ ] 未开始 → [>] 进行中 → [x] 完成
                    ↘
                     [1] 失败1次 → 重试 → [x] 完成
                                    ↘
                                     [!] 跳过(重试仍失败)

中断恢复时: [>] → [ ], [1] → [ ]
  即所有非终态([x]/[!])重置为 [ ]，从第一个 [ ] 开始
```

**选择**: 5 状态（而非 3 状态）
**原因**: [1] 和 [!] 区分了"待重试"和"已放弃"，使重试逻辑显式化。避免 Agent 恢复后尝试重试一个已知会失败的任务。

### D2: 任务清单文件格式

Markdown checkbox 格式，与 `tasks.md` 一致。存储为 `docs/architecture/.task-checklist.md`（隐藏文件，不被视为普通架构文档）。

结构：
```markdown
# 架构文档生成任务清单
**项目**: <name>  **类型**: <type>  **策略**: <letter>
**创建**: <iso-timestamp>  **状态**: 进行中

## 模块文档 (按拓扑排序)
### Layer 0 — 无依赖模块
#### <module> 模块 [进度条]
- [ ] §1 模块概述 (P1)
- [ ] §2 UI组件清单 (P2)
...

## 核心日志文档
### <module> 模块 (核心)
- [ ] §1 文档修订历史 (P2)
...

## 根文档聚合
- [ ] 聚合生成根文档
```

**选择原因**: 与 OpenSpec `tasks.md` 格式一致，Agent 原生理解 checkbox 语法。进度条用 Unicode block 字符提供可视化。

### D3: 方案 Y — 任务清单作为策略扩展

任务清单的生成内容由策略决定：
- **策略 A**: 所有模块 × 所有章节（模块文档 + 日志 + 根文档）
- **策略 B**: 缺失模块 × 所有章节
- **策略 C**: 变更模块 × 变更章节（通过 diff 判断）
- **策略 D**: 仅根文档聚合任务

CP0 检测 `.task-checklist.md` 存在且未完成 → 报告中标注"上次生成未完成，建议恢复" → 用户确认后直接跳转任务执行。

**选择原因**: 不改变 CP0 的用户交互流程，任务清单是策略的"执行计划"而非替代品。

### D4: 失败重试 — 一次重试

```
执行任务 T:
  → 失败: 标记 [1], 保存文件
  → 重试 T:
      → 成功: 标记 [x], 继续
      → 失败: 标记 [!] 并记录原因, 继续下一个任务
```

[!] 项的跳过原因记录在任务清单文件底部：
```markdown
## 跳过清单
- [!] data模块 §4: 源码解析 NullPointerException @ DataParser.java:23
- [!] payment模块 §6: 循环依赖无法绘制 @ Order→Payment→Order
```

### D5: CP0 任务清单检测

CP0 增量检测步骤新增：
```
1. 扫描已有文档 (不变)
2. 扫描已有任务清单:
   - .task-checklist.md 不存在 → 正常流程
   - .task-checklist.md 存在且全部 [x]/[!] → 任务完成，正常流程
   - .task-checklist.md 存在且有 [ ]/[1] → 未完成
     → 报告中标注 "检测到未完成任务清单，上次中断于 <第一个非完成项>"
     → 推荐: "恢复执行"
3. 扫描项目构建文件 (不变)
```

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| 章节级粒度导致任务清单行数多（20模块×12章=240行） | 文件由 Agent 管理，用户不直接阅读。必要时折叠已完成模块 |
| 中断后恢复时模块文档有半截内容 | `[>]` 重置为 `[ ]` 后重新生成该章节，覆盖旧内容 |
| 策略 C 的变更章节判断可能不准 | 优先标记所有章节为待生成，CP2.5 自检时再校验一致性 |
| `.task-checklist.md` 被误删 | 文件丢失 = 无法恢复 = 回到策略 A 全量，不影响正确性 |
