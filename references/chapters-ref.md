# 章节速查参考

本文档提供根文档和模块文档的章节速查，方便快速参考。

## 章节生成优先级

> ★ = 强制且必须标注代码位置 | ✓ = 必须生成 | ○ = 可选（无数据可标注"无"）

| 优先级 | 根文档章节 | 模块文档章节 | 核心日志章节 |
|--------|-----------|-------------|-------------|
| P0 核心 | ★12业务流程图、6依赖图、7依赖分析 | ★4业务流程、★5数据流、★6核心功能流程图 | ★3核心功能日志清单 |
| P1 必须 | 5技术栈、8模块介绍、13数据库、20模块索引、21编译指南 | 1模块概述、3依赖关系、★11关键类和方法 | 2核心判定、5排查指南 |
| P2 补充 | 1修订历史、2架构概览、3项目简介、4术语、9主要组件、10主页架构、11页面跳转、14类图 | 2UI组件、7数据依赖、8依赖场景、9页面路由、10导航示例、12测试策略 | 1修订历史、4日志级别说明 |
| P3 可简 | 15ADR、16接口、17部署、18安全、19风险 | — | — |

> 💡 **最小可行文档**：如果项目简单或时间紧急，至少完成 P0+P1+P2 的全部章节。

## 流程图代码标注规范 ★

> 所有流程图和时序图的每个步骤必须标注方法名和代码位置，并附带**步骤API详解表**和**关键代码示例（必需，非推荐）**。所有图表类型（依赖图、流程图、时序图、导航图、类图、ER图）中涉及代码的节点/参与者都必须标注代码位置。

### 时序图详细度规范 ★

> 🔴 **强制要求：每个核心功能/核心能力都必须有独立的时序图**。不允许将多个核心功能合并为一个粗略时序图。

| 维度 | 最低要求 | 说明 |
|------|----------|------|
| 调用步骤数 | ≥6步（不含返回箭头） | 覆盖完整的调用链路，不允许省略中间层 |
| 参与者数量 | ≥4个 | 展示跨组件/跨层交互 |
| 分层覆盖 | 表现层→业务层→数据层 | 不能跳层（如 UI→Repo 跳过 Service） |
| 返回消息 | 每个请求有对应返回 | 关键返回须标注转换逻辑 |
| 步骤详解表 | 必需 | 每个时序图下方必须附带 |
| 关键代码示例 | 必需 | 每个核心步骤展示代码片段 |

**禁止的粗略模式**：
```
❌ UI->>Repo: getData()              # 跳过Service层
❌ Service->>API: request()           # 跳过Repository层
❌ 只有3-4步的时序图                   # 不够详细
❌ 多个功能合并为一个时序图             # 必须独立
```

**正确的详细模式**：
```
✅ UI->>Service: loadData()          # 表现层
✅ Service->>Logic: execute(params)   # 业务编排层
✅ Logic->>Repo: fetchData(query)    # 数据访问层
✅ Repo->>Local: query()             # 本地数据源
✅ Repo->>Remote: request()          # 远程数据源
✅ Repo-->>Logic: mergedData         # 返回+转换标注
```

### 标注三步法

对每个流程节点，按以下三步完成标注：

```
步骤1: 定位入口 → 找到功能的入口方法（UI事件处理器/后台任务入口）
步骤2: 追踪调用链 → grep/search 方法调用关系，向下追踪到数据层
步骤3: 标注代码位置 → 对每个节点标注 方法名 + 文件相对路径:行号
```

### 流程图节点格式
```
节点ID["步骤名称<br>ClassName.method()<br>文件路径:行号"]
```

### 时序图消息格式
```
箭头消息: 方法名(参数)
Note right of 参与者: 文件路径:行号
```

### 步骤API详解表格式（必需）★
```
| 步骤 | 调用者/组件 | 被调用者 | 方法签名 | 参数 | 返回 | 代码位置 | 说明 |
|------|------------|----------|----------|------|------|----------|------|
```

### 关键类表格格式
```
| 类名 | 文件路径 | 行范围 | 关键方法 | 功能说明 |
```
每个关键方法的子章节应包含：**功能、完整签名、参数、返回、前置条件、副作用、异常处理、调用链、代码示例（必需）**。

### 关键代码展示规范 ★

> ⚠️ **所有涉及代码的图表/章节，都必须在文档中展示对应的关键代码片段**。这不是可选项，而是必需项。

**哪些内容需要展示关键代码**：
1. **业务流程图/时序图**：每个核心步骤都需展示对应的实现代码片段
2. **关键类和方法（模块文档第11章）**：每个关键方法都需展示代码片段
3. **数据流图**：关键数据转换步骤需展示代码
4. **类图**：关键类需展示类定义代码
5. **数据库ER图**：建表语句或 Entity 类代码
6. **导航调用示例（模块文档第10章）**：路由跳转代码

**代码片段格式**：
```
```{语言}
// 文件路径:行号 - 功能说明
方法的关键实现代码（3-15行为宜，过长可省略中间部分用 ... 表示）
`` `
```

**代码片段要求**：
- 必须标注文件路径和行号
- 必须有简短功能说明注释
- 保留核心逻辑，省略无关代码（用 `// ...` 表示）
- 使用对应语言的语法高亮

### 核心方法详情格式（属性面板）★
```
##### `ClassName.method()` — 文件路径:行号

| 属性 | 说明 |
|------|------|
| **功能** | 一段话描述 |
| **完整签名** | `返回类型 方法名(参数类型 参数名)` |
| **参数** | `参数名`: 类型 — 含义 |
| **返回** | `返回类型` — 含义 |
| **调用链** | `调用者A.方法()` → `本方法()` → `被调用B.方法()` |
| **代码示例** | 见下方代码块 |
```

## 章节间交叉引用规范 ★

生成文档时，以下章节必须保持逻辑一致，自检时重点验证：

| 根文档章节 | 交叉引用 | 一致性要求 |
|-----------|---------|-----------|
| 第6章依赖图 ↔ 第7章依赖分析 | 图的边 = 表格行 | 依赖方向和类型一致 |
| 第8章模块介绍 ↔ 第20章模块索引 | 模块列表 | 模块名称、数量、链接一一对应 |
| 第6章依赖图 ↔ 各模块文档第3章 | 依赖关系 | 根文档依赖方向 = 模块文档声明的依赖 |
| 第12章业务流程(§12.3) ↔ 模块文档第6章 | 流程细节 | 根§12.3的每功能时序图必须与模块§6一致（步骤数、参与者、调用顺序），标注来源 |
| 第12章业务流程(§12.4) ↔ 多模块第4-6章 | 跨模块流程 | 端到端流程覆盖所有相关模块的调用链 |
| 第13章数据库 ↔ 模块文档第7章数据依赖 | 数据关系 | 外键关系与模块间数据流一致 |

> 💡 **快速验证法**：从第6章依赖图中读出每条边 (A→B)，验证模块A文档第3章是否声明了对B的依赖
