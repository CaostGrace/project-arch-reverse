# 自检验证详细规格

本文档定义自检验证流程的详细规格，包括报告格式、用户决策点和问题处理方式。

## 检查点2：结果确认流程

### 确认问题清单
- 文档完整性：根文档（21章）？模块文档？索引链接？
- 内容准确性：模块依赖关系？技术栈？数据库设计？
- 可视化检查：Mermaid图表？页面导航？业务流程图？

### 确认方式及后续处理

| 用户回复 | 判定条件 | 后续处理 |
|----------|----------|----------|
| `{"确认": "满足需求"}` | 全部检查项通过 | **直接跳到检查点 2.5（自检验证）** |
| `{"修改": {...}}` | 有具体问题需修改 | 执行修改 → 返回检查点 2 重新确认 |
| `{"更正": "需要人工审核"}` | 用户要求人工介入 | **跳过检查点 2.5 → 直接进入检查点 3（人工更正）** |

### 确认通过后的流程

```
检查点 2 结果确认
        ↓
  ✓ 满足需求
        ↓
检查点 2.5 自检验证 ← 重新评估（最多3次）
        ↓
检查点 3 人工更正（可选）
```

### 确认不通过后的流程

```
检查点 2 结果确认
        ↓
  ✗ 需要修改（具体问题）
        ↓
执行修改 → 更新文档
        ↓
返回检查点 2 重新确认
        ↓
  （循环直到用户确认或进入人工更正）
```

### 修改执行示例

```json
// 用户反馈示例
{"修改": {
  "章节": "第7章",
  "问题": "依赖关系图缺少 XX 模块",
  "期望": "补充 XX 模块的依赖关系"
}}

// 执行：更新 Mermaid 依赖图 + 第7章文本描述
```

## 自检验证循环机制

```
┌──────────────────────────────────────────────────────────────────────┐
│                     自检验证循环（最多3次）                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  ┌─────────────┐     发现问题      ┌─────────────┐                   │
│  │  执行自检   │ ───────────────→ │  记录问题   │                   │
│  └──────┬──────┘                  └──────┬──────┘                   │
│         │                                │                          │
│         │ 无问题                         │ 有问题（<3次）            │
│         ↓                                ↓                          │
│  ┌─────────────┐                  ┌─────────────┐                   │
│  │  验证通过   │                  │  处理问题   │                   │
│  │  继续下一步 │                  └──────┬──────┘                   │
│  └─────────────┘                         │                          │
│                                       重新自检                       │
│                                            │                        │
│                                            ↓                        │
│                                 (达到3次仍有问题)                   │
│                                            ↓                        │
│                                      ┌─────────────┐                │
│                                      │  记录残留问题│               │
│                                      │  继续下一步 │                │
│                                      └─────────────┘                │
└──────────────────────────────────────────────────────────────────────┘

规则：
- 第1次自检：发现并记录问题
- 第2次自检：验证上次问题的处理结果，可能发现新问题
- 第3次自检：最终验证
- 超过3次循环后，无论是否还有问题，都必须继续下一步
- 残留问题需要在最终报告中说明
```

## 自检流程（5个步骤）

### 步骤1：检查根架构文档完整性
- [ ] 检查根文档是否存在
- [ ] 逐章检查根文档（21章），标记缺失的章节
- [ ] 检查每章内容是否完整（非空、非占位符）
- [ ] 输出：根文档完整性报告

### 步骤2：检查模块依赖关系正确性
- [ ] 读取根文档第6章（模块依赖关系图）
- [ ] 读取根文档第7章（依赖关系分析）
- [ ] 交叉验证：
    - 依赖图中显示的依赖关系是否与第7章描述一致？
    - 根文档中列出的所有模块是否都有对应的模块文档？
    - 是否有遗漏的模块或错误的依赖关系？
- [ ] 输出：模块依赖关系验证报告
    - 列出所有已验证正确的依赖关系
    - 列出所有疑似错误或不一致的依赖关系

### 步骤3：检查所有模块文档生成状态
- [ ] 统计项目中的所有模块数量（基于构建文件）
- [ ] 统计已生成的模块文档数量
- [ ] 对比分析：
    - 哪些模块已生成文档？（列出）
    - 哪些模块未生成文档？（列出）
- [ ] 如果有未生成的模块：
    - 分析未生成原因（如：无源码、模块为空、权限问题等）
    - 输出：未生成模块清单及原因分析

### 步骤4：检查核心日志文档完整性
- [ ] 识别项目中的核心模块（用户可达界面 + 后台运行能力 + 模块复杂度 + 用户手动指定）
- [ ] 统计已生成的核心日志文档数量
- [ ] 对比分析：
    - 哪些核心模块已有日志文档？（列出）
    - 哪些核心模块缺少日志文档？（列出）
- [ ] 对已有日志文档检查：
    - 日志清单是否覆盖所有核心功能？（检查第3章，参照 `log-extraction-guide.md` 的各语言日志模式）
    - 每个核心功能是否有至少3条关键日志？
    - 日志是否标注了完整的代码位置？
    - 排查指南是否具有可操作性？（检查第5章）
- [ ] 输出：核心日志文档完整性报告

### 步骤5：汇总报告并决策

## 问题分类与处理方式

| 问题类型 | 处理方式 |
|----------|----------|
| 根文档章节缺失 | 立即生成缺失章节 |
| 根文档内容不完整 | 补充完善章节内容 |
| 模块依赖关系错误 | 修正依赖关系描述，重新生成相关图表 |
| 模块文档缺失 | 立即生成该模块文档 |
| 模块文档内容问题 | 修正该模块文档内容 |
| Mermaid图表错误 | 重新生成正确的图表 |
| 链接失效 | 修复链接 |
| 核心日志文档缺失 | 立即扫描生成该模块的核心日志文档 |
| 核心日志覆盖不完整 | 补充扫描遗漏日志，更新日志文档第3章 |

## 用户决策点

### 第 1/3 次自检
```
检测到以下问题（已在本次处理）：
1. 根文档第X章缺失 → 已生成
2. 模块A文档缺失 → 已生成
3. 依赖关系错误 → 已修正

✓ 本次自检问题已全部处理，是否继续验证？

[1] 继续自检验证（重新执行检查点 2.5）
[2] 跳过验证，继续到检查点 3（人工更正）
```

### 第 2/3 次自检
```
检测到以下问题（已在本次处理）：
1. 图表格式错误 → 已重新生成
2. 链接失效 → 已修复

✓ 问题已处理，是否继续验证？

[1] 继续自检验证（重新执行检查点 2.5）
[2] 跳过验证，继续到检查点 3（人工更正）
```

### 第 3/3 次自检（最终验证）
```
⚠️ 已达到最大循环次数（3次）

残留问题（无法自动处理）：
1. 模块X依赖关系需要人工确认
2. 数据库设计部分信息缺失

是否继续？

[1] 记录残留问题，继续到检查点 3（人工更正）
[2] 尝试手动修复残留问题
```
