# 自检验证详细规格

本文档定义自检验证流程的详细规格，包括报告格式、用户决策点和问题处理方式。

## 检查点2：结果确认流程

### 确认问题清单
- 文档完整性：根文档（21章）？模块文档？索引链接？
- 内容准确性：模块依赖关系？技术栈？数据库设计？
- 可视化检查：Mermaid图表？页面导航？业务流程图？

### 确认方式及后续处理

| 用户回复 | 判定条件 | 后续处理 |
|----------|----------|----------|
| `{"确认": "满足需求"}` | 全部检查项通过 | **直接跳到检查点 2.5（自检验证）** |
| `{"修改": {...}}` | 有具体问题需修改 | 执行修改 → 返回检查点 2 重新确认 |
| `{"更正": "需要人工审核"}` | 用户要求人工介入 | **跳过检查点 2.5 → 直接进入检查点 3（人工更正）** |

### 确认通过后的流程

```
检查点 CP5 结果确认
        ↓
  ✓ 满足需求
        ↓
检查点 2.5 自检验证 ← 硬门禁（无次数上限，阻塞委托CP3回归）
        ↓
检查点 3 人工更正（可选 / CP6委托回归）
```

### 确认不通过后的流程

```
检查点 CP5 结果确认
        ↓
  ✗ 需要修改（具体问题）
        ↓
执行修改 → 更新文档
        ↓
返回检查点 2 重新确认
        ↓
  （循环直到用户确认或进入人工更正）
```

### 修改执行示例

```json
// 用户反馈示例
{"修改": {
  "章节": "第7章",
  "问题": "依赖关系图缺少 XX 模块",
  "期望": "补充 XX 模块的依赖关系"
}}

// 执行：更新 Mermaid 依赖图 + 第7章文本描述
```

## 自检验证循环机制（硬门禁 — 无次数上限）

```
┌──────────────────────────────────────────────────────────────────────┐
│                     自检验证循环（硬门禁）                              │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  ┌─────────────┐     发现问题      ┌─────────────┐                   │
│  │  执行自检   │ ───────────────→ │  分析问题   │                   │
│  └──────┬──────┘                  └──────┬──────┘                   │
│         │                                │                          │
│         │ 全部通过                       ├── 可自动修复               │
│         ↓                                │   └→ 修复 → 重新自检      │
│  ┌─────────────┐                         │   同问题第3次仍失败       │
│  │   ✅ 完成   │                         │   → 标记阻塞 → 委托CP3   │
│  └─────────────┘                         │                          │
│                                          └── 不可自动修复            │
│                                              └→ 标记阻塞 → 委托CP3  │
│                                                   ↓                  │
│                                              CP3 人工处理             │
│                                                   ↓                  │
│                                              回归 CP6              │
│                                              （全项重新自检）         │
└──────────────────────────────────────────────────────────────────────┘

规则：
- 🔴 唯一终止条件：全部 6 项检查通过
- 🔴 不可带残留问题退场（除非用户通过 CP3 明确接受）
- 🔴 总轮次无上限，但防死循环策略保底
```

## 自检流程（6 个步骤）

### 步骤1：检查模块覆盖与完整性
- [ ] 统计项目中的所有模块数量（基于构建文件识别）
- [ ] 统计已生成的模块文档数量
- [ ] 逐文档检查每模块章节完整性：codegraph 模式检查 14 章（含 §13 重构建议 + §14 死代码），手动模式检查 12 章
- [ ] 对比分析：缺失模块文档？缺失章节？
- [ ] **若有 `.task-checklist.md`**：对比任务清单预期任务数 vs `[x]` 完成数 vs `[!]` 跳过数；`[!]` 项列为已知不完整
- [ ] 输出：模块覆盖与完整性报告

### 步骤2：检查模块间依赖一致性
- [ ] 遍历每个模块文档第3章声明的依赖关系
- [ ] 交叉验证：A 声称依赖 B → B 是否真实存在？
- [ ] 验证依赖方向与构建文件解析结果一致
- [ ] 输出：模块间依赖一致性报告
    - 列出所有验证一致的依赖关系
    - 列出所有方向不一致或目标不存在的依赖

### 步骤3：检查根文档完整性
- [ ] 检查根文档是否存在
- [ ] 逐章检查根文档：codegraph 模式检查 23 章（含 §22 重构建议 + §23 死代码），手动模式检查 21 章
- [ ] 检查每章内容是否完整（非空、非占位符），§12 是否有 §12.1-§12.4
- [ ] 输出：根文档完整性报告

### 步骤4：检查根文档聚合正确性 ★
- [ ] 根文档§6依赖图 ↔ 各模块§3：图中每条边 (A→B) 在 A 模块§3 中可找到
- [ ] 根文档§12.3核心功能 ↔ 各模块§6：每功能在对应模块文档中存在
- [ ] 根文档§13 ER图 ↔ 各模块§7：每个实体至少在一个模块§7中被引用
- [ ] 根文档§14类图 ↔ 各模块§11：每个类至少在一个模块§11中有定义
- [ ] 输出：根文档聚合正确性报告

### 步骤5：检查两层日志文档完整性 ★
- [ ] 识别日志触发模块列表中的所有模块（核心模块 + codegraph 触发模块 + 调用链模块）
- [ ] 统计第一层日志文档：每个触发模块是否有 `{模块}_核心日志.md`（8章/codegraph | 5章/手动）
- [ ] 第二层日志检查（codegraph 可用时）：
    - 日志触发标记清单中每项函数是否有 `{函数名}_关键函数日志.md`
    - 日志触发标记清单中每项场景是否有 `{场景名}_场景日志.md`
- [ ] 手动模式检查：所有日志文档头部是否包含 `[手动模式]` 标注
- [ ] 对已有日志文档检查：
    - 日志清单是否覆盖所有核心功能？
    - 每个核心功能是否有至少3条关键日志？
    - 日志是否标注了完整的代码位置？
- [ ] 检查架构变更模块的日志是否已同步更新（第一层 + 第二层）
- [ ] 输出：两层日志文档完整性报告（含覆盖率统计）

### 步骤6：检查聚合图表交叉验证 ★
- [ ] 根文档§12.3时序图 ↔ 模块§6时序图：步骤数、参与者列表、调用顺序三者一致
- [ ] 根文档§12.4跨模块时序图 ↔ 涉及模块§6：每个步骤的所属模块和代码位置匹配
- [ ] 不一致时以模块文档为准修正根文档
- [ ] 输出：聚合图表交叉验证报告

## 硬门禁判定规则 ★

| 情况 | 处理 | 循环策略 |
|------|------|---------|
| 全部 6 项通过 | ✅ 完成，继续 CP3 或结束 | — |
| 可自动修复（缺失/不一致/语法错误） | 自动修复 → 重新全项自检 | 同问题第3次仍失败 → 标记阻塞 → 委托 CP7 |
| 不可自动修复（架构判断需领域知识） | 立即标记阻塞 → 委托 CP7 | CP3 处理完 → 回归 CP6 |
| 非标准结构无法解析 | 立即标记阻塞 → 委托 CP7（不做自动修复尝试） | CP3 处理完 → 回归 CP6 |

## 防死循环策略 ★

| 触发条件 | 处理 |
|----------|------|
| 同一检查项的同一问题经 3 次自动修复仍失败 | 标记阻塞 → 委托 CP7，不再自动修复该项 |
| 全项自检累计 5 轮后仍有阻塞项 | 暂停 → 请求用户决策：继续 / 降级接受 / 永久跳过 |
| 用户通过 CP3 明确接受某检查项为残留 | 标记"用户接受" → 回归 CP6 时跳过该项 |

## 问题分类与处理方式

| 问题类型 | 处理方式 |
|----------|----------|
| 根文档章节缺失 | 立即生成缺失章节 |
| 根文档内容不完整 | 补充完善章节内容 |
| 模块依赖关系错误 | 修正依赖关系描述，重新生成相关图表 |
| 模块文档缺失 | 立即生成该模块文档 |
| 模块文档内容问题 | 修正该模块文档内容 |
| Mermaid图表错误 | 重新生成正确的图表 |
| 链接失效 | 修复链接 |
| 核心日志文档缺失 | 立即扫描生成该模块的第一层模块级日志文档 |
| 函数级日志缺失 | 立即生成对应的 `{函数名}_关键函数日志.md` |
| 场景日志缺失 | 立即生成对应的 `{场景名}_场景日志.md` |
| 核心日志覆盖不完整 | 补充扫描遗漏日志，更新日志文档 |
| 手动模式标注缺失 | 补充 `[手动模式]` 标注 |

## 用户决策点

### 自检通过
```
✅ 全部 6 项检查通过！
继续到 CP7（人工更正）或完成。
```

### 自检发现问题（可自动修复）
```
检测到以下问题（已在本次自动修复）：
1. 模块A文档缺失 → 已生成
2. 依赖声明不一致 → 已修正
3. 根文档§12.3时序图与模块§6不一致 → 已重新聚合

重新执行全项自检...
```

### 自检发现阻塞项
```
🚫 发现不可自动修复的阻塞项：

1. [检查项] 模块X依赖关系 — 自定义构建系统，无法自动解析
   建议：人工确认模块X的实际依赖关系
2. [检查项] 模块Y架构判断 — 需要领域知识判断
   建议：确认模块Y的业务定位

阻塞项已委托 CP7 处理。处理完成后将自动回归 CP6。
[1] 进入 CP3 处理阻塞项
```

### 防死循环触发（5轮后）
```
⚠️ 已进行 5 轮自检，仍存在阻塞项：

阻塞项：
1. [Step 4] 模块X聚合正确性 — 自动修复3次仍未通过

请选择：
[1] 继续自检（再试）
[2] 降级接受：标记为"用户接受"，跳过该项
[3] 永久跳过：不再检查该项
```
