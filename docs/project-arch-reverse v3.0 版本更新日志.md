## 一、重大功能新增

| 功能 | 说明 |
|------|------|
| **CodeGraph 主分析引擎** | 集成 `@optave/codegraph` 作为主分析引擎（v3.11.1, 34 语言支持），替代手动 8 步扫描。不可用时自动降级。新增核心能力档案生成、入口点扫描（78 个入口点）、认知复杂度分析 |
| **模块优先生成策略** | 按拓扑排序分层生成全部模块文档 → 再聚合根文档。根文档 §12 全量聚合展示（§12.1 概览 → §12.2 索引表 → §12.3 模块汇总 → §12.4 跨模块分析） |
| **章节级任务清单机制** | `.task-checklist.md` 持久化进度追踪，支持中断恢复。5 种状态标记：`[ ]` `[>]` `[1]` `[x]` `[!]` |
| **两层日志生成体系** | 日志从"核心模块"维度下沉到"函数/流程"维度。第一层：模块级 8 章日志；第二层：函数级 + 场景级精细日志。日志触发条件：核心模块 ∪ 认知复杂度>10 ∪ 被调用次数>3 ∪ 关键调用链 |
| **架构重构建议与死代码分析** | 根文档 §22 重构建议（manifesto违规 + SCC循环依赖 + 复杂度热点）+ §23 死代码（dead节点 + 0调用者 + 死模块） |
| **执行路径日志分析** | 日志文档从 5 章扩展为 8 章：新增 §3 执行路径日志追踪、§4 错误传播、§5 日志覆盖评估、§8 故障排查决策树 |
| **日志文档可执行化** | 所有日志清单增加平台实际输出示例和 grep 命令列。§7 增加各平台日志格式速查。§8 故障排查改为 4 要素格式（命令+预期输出+异常输出+fallback）。日志缺陷严重度分级（🔴P0/🟡P1/🟢P2）+ 自动埋点建议 |
| **文档渲染质量双门禁** | 门禁1（CP4 生成时质检）：Mermaid 10 条规则 + 表格列数 + 代码块 + 文档结构。门禁2（CP6 自检时二次校验）：包含链接有效性等全局检查。不可修复的标记跳过入报告 |
| **生成强制执行纪律** | CP4 生成阶段铁律（5 条禁止行为）、`[!]` 仅限不可恢复错误、CP6 文档缺失不可"用户接受"退出 |

## 二、日志体系全面升级（v3.0 核心变更）

| 变更 | 说明 |
|------|------|
| **两层日志体系** | 模块级日志（8章） + 函数级日志（5章）+ 场景日志（6章）。日志触发从模块维度扩展到函数/流程维度，利用 codegraph 精确的认知复杂度和被调用次数数据 |
| **严重度分级与建议生成** | 🔴P0 严重（整链零日志/入口缺失/异常缺失）→ 🟡P1 警告（出口缺失/覆盖<50%）→ 🟢P2 合格。基于函数名语义 + 调用链位置自动推断埋点建议内容、级别和优先级 |
| **平台输出示例** | 6 个平台（Android/iOS/Java后端/Node.js/Flutter/HarmonyOS）的真实日志输出格式。每条日志附带可直接复制的 grep 排查命令 |
| **场景日志** | 跨模块端到端调用链日志追踪。新增 §6 改进建议：按模块分组列出具体埋点方案 |
| **根文档日志缺陷汇总** | 全项目日志覆盖统计 + 🔴P0 严重缺陷列表 + 🟡P1 警告列表 |
| **强制生成全量** | 模块文档 + 日志触发模块日志 = 必须全部生成，不可省略。禁止询问用户、禁止"基础完成"标注、禁止建议"后续补充" |

## 三、CodeGraph 深度集成

| 变更 | 说明 |
|------|------|
| **分析管道** | Step A：查询节点数据（entry/core/dead/utility, 复杂度排序, 跨模块调用链, codegraph check）。Step B：为每个 core 节点生成核心能力档案（用途+调用者+被调用者+场景+时序图+流程图）。Step C：章节映射。Step D：日志触发标记输出 |
| **入口点扫描** | 8 平台 78 个入口点自动检测（UI触发/系统触发/外部事件），支持 ContentProvider/@Scheduled/BroadcastReceiver 等系统入口 |
| **降级回退** | npm 不可用/安装失败/构建失败/用户跳过 → 自动降级为手动 8 步扫描。降级不报错，报告标注原因 |
| **npm 环境检测** | CP2 全局安装前增加用户确认检查点，用户拒绝自动降级 |
